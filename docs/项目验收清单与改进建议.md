## 💡 我的5点以上思考

### 1. 架构设计 - 职责分离原则

**当前设计的优点**：
- ✅ **Parser 负责提取**：只关心从文件中提取文本块
- ✅ **Agent 负责理解**：使用 LLM 理解费用语义
- ✅ **SmartCRUD 负责决策**：判断 CREATE/UPDATE/NO_CHANGE
- ✅ **Workflow 负责编排**：协调整个流程

**改进建议**：
```python
# 建议添加独立的验证层
class Validator:
    def validate_amount_consistency(self, decision):
        """验证金额一致性"""
        pass
    
    def validate_duplicate(self, decision, existing_records):
        """验证重复"""
        pass
    
    def validate_conflict(self, decision, existing_records):
        """验证冲突"""
        pass
```

**好处**：
- 验证逻辑独立，易于测试
- 可以灵活组合不同的验证规则
- 便于后续扩展新的验证类型

---

### 2. LLM Prompt 工程 - 少即是多

**当前问题**：
- Prompt 过于复杂（100+ 行）
- 规则过多，LLM 难以全部遵守
- 容易产生 PENDING_REVIEW

**改进建议**：
```python
# 方案A：分阶段处理
# 第一阶段：提取（简单 Prompt）
EXTRACTION_PROMPT = """
只提取账单中的事实：
1. 费用名称
2. 金额
3. 币种
4. 单据号
"""

# 第二阶段：验证（独立 Prompt）
VALIDATION_PROMPT = """
检查提取结果是否合理：
1. 金额是否与明细一致
2. 币种是否缺失
"""

# 第三阶段：决策（SmartCRUD 程序逻辑）
# 不依赖 LLM，完全由程序判断
```

**好处**：
- 每个 Prompt 职责单一，更可控
- 减少 LLM 的认知负担
- 提高准确性和一致性

---

### 3. 数据建模 - 明细与汇总分离

**当前设计**：
- 主记录存储总额
- 明细项存储在 JSON (line_items)

**优点**：
- ✅ 符合财务记账原则（一张单据一条记录）
- ✅ 数据库简洁
- ✅ 易于对账

**潜在问题**：
- ❌ 查询明细项需要解析 JSON
- ❌ 无法直接按费用类型统计

**改进建议**：
```sql
-- 方案：主从表设计
CREATE TABLE ledger_records (
    record_id VARCHAR(50) PRIMARY KEY,
    document_number VARCHAR(100),
    total_amount DECIMAL(18,4),
    currency VARCHAR(3)
);

CREATE TABLE ledger_line_items (
    line_id VARCHAR(50) PRIMARY KEY,
    record_id VARCHAR(50) REFERENCES ledger_records(record_id),
    charge_name VARCHAR(200),
    amount DECIMAL(18,4),
    currency VARCHAR(3)
);

-- 好处：
-- 1. 可以直接查询明细
-- 2. 可以按费用类型统计
-- 3. 保持数据规范化
```

### 4. 错误处理 - 优雅降级

**当前状态**：
- 部分错误会导致整个文件处理失败
- 没有详细的错误分类

**改进建议**：
```python
class ProcessingResult:
    status: Literal["SUCCESS", "PARTIAL_SUCCESS", "FAILED"]
    processed_decisions: List[Decision]
    skipped_decisions: List[Decision]
    errors: List[ErrorDetail]

# 示例：即使部分费用提取失败，其他费用仍然保存
# 而不是整个文件都失败
```

**错误分类**：
```python
class ErrorSeverity(Enum):
    WARNING = "warning"    # 可以继续，但需要注意
    ERROR = "error"        # 当前项失败，其他继续
    FATAL = "fatal"        # 整个处理失败
```
