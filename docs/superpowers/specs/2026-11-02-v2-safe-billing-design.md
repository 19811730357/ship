# V2 账单处理调整设计

本设计对应用户已确认的渐进重构方案：保留现有项目，统一模型提取、候选检索、变更提议、程序验证和事务提交。

## 约束

- 项目、原始材料、缓存、临时目录、日志、备份和测试文件均位于 D 盘。
- 不访问真实模型、OCR、OSS 或用户数据库进行自动化测试；不读取或复制真实密钥。
- 原有账本表保持可读，不删除、覆盖或自动拆分历史整单记录。
- 默认预览。预览不写业务账本；确认提交后再核验版本并事务写入。
- 模型置信度不代替身份、修订依据、字段证据和硬规则。

## 数据和处理

费用逐行提取，拥有稳定记录 ID；同名费用不合并。MBL/HBL/订舱号/箱号保留类型及多值。原币金额、结算金额、单价、单据总额、已付额、余额分别保存。字段证据关联来源摘要、块 ID、页码和行列；来源位置不充当跨版本身份。

模型先提取事实；程序限定记账主体检索候选；涉及旧账的语义修订可再调用模型，但候选 ID 和提取事实不可被模型擅自改变。程序合并白名单补丁后校验。无匹配但身份不足、多候选、无明确修订依据、证据缺失、币种未知等均待复核。

待复核界面显示原文、候选和差异。人工选择目标/批准新增/修正金额必须填写说明，重新检查主体、币种、金额、单据完整性和版本；人工批准不能跳过结构或合计冲突。

同一单据先整体核对再提交；提交阶段重新读取当前版本，并在同一事务写费用、单据关系、前后值审计和来源状态。数据库失败全部回滚。外部 JSON 导出失败不会重放已提交业务操作。

文件状态区分解析失败、待复核、已提交、无费用。仅成功提交且处理配置一致的来源可复用；幂等按主体与来源区分，待复核和失败允许重试。重复业务费用还须依赖身份与证据核对。

EML 递归解析附件并保留父子关系。图片/扫描 PDF 调用配置的 OCR/OSS；没有结果时失败，不返回成功占位。超时保留待清理云对象状态，不假定远端已停止读取。

## 验收

覆盖不同主体同号、多条同名费用、无修订依据的差异、白名单补丁继承、负/零及币种歧义、整单金额冲突、版本竞争、事务回滚、来源重试与查重、完整快照往返、图片 OCR 和 EML 附件。真实服务未调用时明确说明未验收，不以离线通过替代联调。
