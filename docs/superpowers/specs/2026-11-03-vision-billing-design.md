# 无 OSS 视觉识别与账单自动处理

用户已在本次对话确认实施：保留现有文本模型，增加云端视觉识别入口，落实缺省 AR、问题分级及金额来源核对。视觉服务由用户申请并配置；开发不调用真实付费接口，不修改真实数据库。

## 数据流与边界

- 文字 PDF 和 EML 正文保持原生解析。图片、扫描 PDF 页面通过支持 Base64 的视觉接口识别，原 URL 型 OCR＋OSS 作为可选后端。
- 每个来源页面只使用一份正式识别结果；原件、识别原始响应和每次解析观察分别保存在项目 D 盘。视觉请求的密钥及 Base64 请求体不写日志。
- EML 附件递归处理，保留父子来源关系。只有明确识别为无关装饰的素材才可跳过并留下依据；账单识别失败不能静默忽略。
- 方向策略在候选匹配后执行：原文明确值优先，缺失时继承唯一旧账，再对新账采用主体配置的 AR 默认值。记录来源和规则依据，明确冲突仍需复核。
- 允许原始费用账本保留未映射费用名，显示警告，不把模型建议自动升级为批准字典。修改已有费用仍要求唯一身份和修订授权。
- 问题保留代码、严重度、解决状态和来源；已被规则解决的问题不再阻塞，系统识别失败与账单业务冲突分开展示。可补提取的身份字段最多定向重试一次。
- 明细金额、总额、单价和余额分别保存。总额原文不能支持明细金额；原文有总额而模型漏提取时不能跳过核对。300 明细／245 总额必须显示差额 55 并阻止费用提交。

## 配置

`OCR_BACKEND=vision`；`VISION_BASE_URL` 为兼容 chat completions 的服务基础地址；`VISION_MODEL` 必填；`VISION_API_KEY` 可单独配置，未配置时允许复用 `DASHSCOPE_API_KEY`；`PDFTOPPM_PATH` 可指定扫描页渲染工具；`DEFAULT_POSTING_TYPE=AR`；`ALLOW_UNMAPPED_CHARGES=true`。

旧 `OCR_BACKEND=remote` 保留 `OCR_URL`、认证及 OSS 配置。实际 `.env` 不改写，模板中的密钥改为占位符。所有配置状态仅显示是否配置，不显示密钥。

## 验收

1. 未配置 OSS 时，用 HTTP 替身完成图片／扫描页识别；文字 PDF 不调用视觉接口。
2. EML 正文和真实账单附件被处理，明确无关素材不生成费用；重复识别／提交不新增重复费用。
3. 新账方向缺失按配置为 AR；旧 AP 缺失新方向时继承 AP；原文方向冲突不被默认值掩盖。
4. 未映射原始费用可保留并显示警告，严格模式仍可要求批准映射。
5. 300／245、错误使用 total 作为明细、遗漏原文明示总额均不能提交费用；原有主体、版本、事务及修订保护继续通过回归。
6. 模型／视觉配置缺失提示具体配置名；不调用真实模型、OCR、OSS 或 MySQL；无可控 C 盘写入。
