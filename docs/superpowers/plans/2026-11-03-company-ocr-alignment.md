# 公司 OCR 输入协议对齐 Implementation Plan

**Goal:** 遵照用户最新明确约束，只依赖题方提供的 OCR 接口，不要求另行申请视觉模型。

**Architecture:** 工作流和界面默认选择 `remote`，沿用 `POST JSON {file, task, callBack, taskType}` 协议。URL 文件可直接调用；本地文件若没有可达 URL／上传机制，则明确报告输入协议缺项。OSS 只是已有可选 URL 桥接，不伪装成题方必需配置。旧视觉适配器不作为题目默认要求。

**Constraints:** 公司只提供请求示例，未提供上传接口、文件 URL 或 Base64／multipart 文档；不臆造协议、不建立公网隧道、不调用真实服务。实际 `.env` 和密钥不改写，全部项目产物与测试临时目录在 D 盘。

- [x] 增加默认 remote、处理签名、题方 JSON 请求及 URL 无 OSS 路径测试，先观察预期失败。
- [x] 修改工作流缺省后端和本地输入缺项错误，保留原件与结构化错误。
- [x] 修改界面配置状态：区分接口地址配置与本地文件输入就绪；不索取视觉模型，也不把 OSS 说成接口本身要求。
- [x] 更新配置模板和公司 OCR 配置指南，注明当前缺文件上传／链接获取方式。
- [x] 运行针对性及完整离线回归，记录真实 OCR 尚未联调，不宣称本地图片已跑通。
