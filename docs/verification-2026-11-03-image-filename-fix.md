# V4 图片上传文件名兼容修复

## 现象与证据

用户在界面上传 `001-图片示例.png`，显示“识别／配置问题：OCR识别失败：OCR未返回可识别文本”。最近两次来源记录的图像 SHA256 均与此前成功图片一致，但公司原始响应为 `success=true`、`data.list=[]`、`pages_split=[]`。这不是模型漏读已经返回的费用。

同图对照实测：

| 云端对象文件名 | 签名链接下载 | 公司 OCR |
|---|---|---|
| 旧逻辑预编码中文名 `001-%E5…png` | HTTP 200，字节 SHA256 与原图一致 | `success=true`，0 条识别记录 |
| ASCII 文件名 `invoice.png` | HTTP 200，字节 SHA256 与原图一致 | 返回单号及费用，1 条识别记录 |

OSS 凭据及下载链路在本次检查中正常。旧逻辑先对原文件名 URL 编码，SDK 再生成签名 URL，产生 `%25` 等编码；这条路径触发公司 OCR 空结果。对照表能证明对象命名影响当前服务，不能据此断言服务端内部具体如何处理 URL。

## 修复

`src/billing_agent/parsers.py` 的 OCR 对象名使用 `billing-ocr/<随机UUID>/document.<原扩展名>`，扩展名规范为小写，不再将用户原名放入云端对象键。原始中文文件名仍保留在 `source_file` 和 `metadata.original_filename`，来源身份、金额和币种规则不变。

空识别增加 `OCR_EMPTY_RESULT` 标记及“公司OCR返回结果为空”的具体提示，继续保存原始响应、阻止无内容材料进入正常提取。没有用默认金额或重放旧结果冒充识别成功。

## 验证

1. 新增中文名、含百分号名及上游空响应三项回归，先观察预期失败，再修复通过。
2. 完整离线回归 **279 passed, 1 warning**，警告为既有 PyPDF2 弃用提示。
3. 用修复后的实际解析器读取 `001-图片示例.png`，真实完成 OSS 上传、公司 OCR 和临时对象清理，返回单号 `ORFR1618731`、费用 `5.00` 和 `21.90`，10 个来源文本块，错误为空，无待清理对象。公司仍未返回币种，按用户约定保留未知并人工核对。

对照结果：`output/diagnostics/image-url-comparison.json`。

修复后实测：`output/diagnostics/image-filename-fix-result.json`。
