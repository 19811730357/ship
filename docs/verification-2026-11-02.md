# V2 调整与验证记录

日期：2026-11-02。范围：当前 V2 项目的渐进重构；未连接用户真实数据库，未调用真实模型、OCR 或 OSS。

## 已实现

- 演示、内存和数据库使用同一套费用规划与提交规则。默认预览，提交入口独立。
- 逐条费用保存；单据、费用、类型化编号、来源状态、变更历史分表。同名费用不合并。
- 主体隔离；候选身份核对；多候选及无修订依据的差异进入复核。模型待复核意见和高置信度都不能绕过程序校验。
- 费用字典由可信应用上下文提供，模型不能自行提供字典或编造标准费用代码；人工映射只适用于本次费用。
- 金额、单价、原币、结算金额、汇率、原单总额、已付额、余额分别处理。金额使用 Decimal，超出当前 MySQL DECIMAL(24,8) 范围时复核，禁止静默舍入。
- 字段补丁保留未提供字段、历史和版本；事务内锁定账套、重验候选与版本、写账本和审计。重复预览及不同来源的重复新增均有提交阶段保护。
- UI 支持选择候选、明确新增、修正字段、填写依据及部分提交后继续复核。解析问题可经人工确认与费用无关后排除；模型漏提取和单据合计问题不能通过该入口绕过。
- EML 优先纯文本正文，保留邮件头与递归附件；文本块保留来源、页、行列。图片和扫描页经配置的 OSS/OCR 处理；失败不作为成功占位。
- 原文件和每次不可变解析观察记录归档到 D 盘，观察记录包含原始 OCR 响应、错误和附件引用。超时对象保留待清理记录。
- 完整账本快照可重新导入。旧表只读保留；无记录分类的旧整单材料作为 legacy_summary 复核，不自动拆分。首次升级已有本地 SQLite 时先备份。
- 启动脚本、临时目录、可配置缓存、日志和 Streamlit 全局文件定位到项目 D 盘；密码不输出到日志。
